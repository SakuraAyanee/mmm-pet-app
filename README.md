# Mamimi Desktop Pet

一个使用 Vue 3、TypeScript、Tauri 2、PixiJS 和 Spine 构建的 Windows 透明桌面宠物实验项目。

项目当前重点不是简单地把图片悬浮在桌面，而是逐步验证一套完整的桌宠技术链路：透明无边框窗口、像素级穿透、窗口拖动、高清骨骼渲染、可恢复动画状态机，以及未来隐私优先的桌面环境感知。

> 当前处于个人学习和原型开发阶段。项目使用的角色形象与 Spine 素材仅用于本地研究和技术验证；相关角色及素材权利归原权利方所有。公开分发或商业使用前必须确认授权范围。

## 当前能力

- 在透明、无边框的 Tauri 窗口中渲染 Spine 3.6 角色；
- 使用 2～3 倍 Canvas 渲染倍率改善高分屏清晰度；
- 角色显示尺寸支持 60%～140% 调整与本地持久化；
- 透明区域可以穿透到桌面或下层应用；
- 默认 `wait` 姿势会自动生成 Alpha 命中蒙版；
- 角色本体和三横线按钮都可以拖动窗口；
- 缩放编辑状态下仍可移动窗口；
- 支持窗口居中、退出以及“总在最前”开关；
- 提供可拖动的点击动画测试工作台；
- 自动读取 Spine 动画中的 `loop_start` 与 `relay` 事件；
- 支持作者提供的动作链和可选 `face_*` 表情覆盖；
- 使用可中断动画状态机处理连续点击，保证收手动画不会被直接跳过。

## 操作方式

| 操作 | 结果 |
| --- | --- |
| 单击角色 | 播放当前保存的点击动画 |
| 按住角色并移动 | 拖动桌宠窗口 |
| 拖动三横线按钮 | 拖动桌宠窗口 |
| 右键角色 | 打开功能菜单 |
| 调整大小 | 显示缩放框、百分比、重置与确认按钮 |
| 动画测试 | 选择动作、表情并预览或保存为点击动画 |
| 重置位置 | 将窗口移动到屏幕中央 |
| 总在最前 | 切换窗口置顶状态 |

## 技术栈

| 层次 | 技术 |
| --- | --- |
| 前端组件 | Vue 3 Composition API |
| 开发语言 | TypeScript 6 |
| 构建工具 | Vite 8 |
| 桌面容器 | Tauri 2 |
| 原生端 | Rust |
| 2D 渲染 | PixiJS 4.8.9 |
| 骨骼动画 | pixi-spine 1.5.16 / Spine 3.6 数据 |
| 状态保存 | localStorage |

项目使用旧版 PixiJS 与 pixi-spine，是为了兼容现有 Spine 3.6 模型及其 clipping 数据。升级渲染栈前需要建立动画和截图回归测试。

## 架构

```text
App.vue
└── PetAvatar.vue
    ├── Tauri 窗口操作
    ├── 拖动、缩放与右键菜单
    ├── Alpha 命中和透明穿透
    ├── 动画测试工作台
    └── SpineAvatar.vue
        ├── PixiJS Application
        ├── Spine 资源加载与布局
        ├── 高清 Canvas 渲染
        ├── 默认命中蒙版采集
        ├── 多轨道表情与局部动作
        └── 可中断动画状态机
```

职责划分：

- `PetAvatar.vue` 管理用户交互和原生窗口行为；
- `SpineAvatar.vue` 管理 WebGL、骨骼、动画轨道和播放生命周期；
- `src-tauri/capabilities/default.json` 限制前端可调用的窗口能力；
- `public/spine/mamimi/` 保存当前模型的 JSON、Atlas 和纹理。

## 动画播放模型

模型事件中包含：

```text
loop_start → 可循环片段起点
relay      → 动作结束后的复位动画
```

播放器将一次动作拆为：

```text
intro → loop × N → relay → wait
```

连续操作采用单槽等待队列：

```text
当前动作播放中
→ 只保存用户最后一次请求
→ 在安全动画边界退出
→ 完整执行 relay
→ 播放最后请求的动作
```

这避免直接 `clearTracks()` 跳过 `arm_down*` 后产生手臂、附件或表情错位。

Spine 轨道用途：

```text
Track 0 → 身体主动画、relay、wait
Track 1 → yes / no 等局部动作
Track 2 → 用户主动选择的表情覆盖
```

表情默认设置为“跟随原动画”，只有用户明确选择时才覆盖，并在复位阶段淡出。

## 环境要求

当前主要开发和验证环境为 Windows。

需要安装：

- Node.js 与 npm；
- Rust stable toolchain；
- Visual Studio Build Tools 或 Visual Studio Community；
- “使用 C++ 的桌面开发”工作负载；
- WebView2 Runtime，现代 Windows 通常已自带。

验证环境：

```powershell
node --version
npm --version
rustc --version
cargo --version
```

如果 Rust 已安装但终端无法识别 `rustc` 或 `cargo`，请先关闭并重新打开 PowerShell，使 PATH 更新生效。

## 本地运行

安装依赖：

```powershell
npm install
```

只运行网页预览：

```powershell
npm run dev
```

浏览器预览可以检查 Vue 和 Spine 渲染，但不能验证原生窗口拖动、置顶和穿透。

以 Tauri 桌面窗口运行：

```powershell
npx tauri dev
```

构建前端：

```powershell
npm run build
```

检查 Rust 原生端：

```powershell
cd src-tauri
cargo check
```

生成桌面安装包：

```powershell
npx tauri build
```

## 验证清单

每次修改窗口、渲染或动画逻辑后，至少检查：

- [ ] `npm run build` 通过；
- [ ] `cargo check` 通过；
- [ ] 透明区域可以点击到下层应用；
- [ ] 角色可拖动，单击不会被误判为拖动；
- [ ] 缩放、重置和确认行为正常；
- [ ] 60% 与 140% 时角色和 Canvas 同步变化；
- [ ] 眼睛、眉毛和裁剪附件显示正常；
- [ ] `anger1 → touch` 等连续动作会先执行 relay；
- [ ] 快速选择多个动作时只播放最后一个等待项；
- [ ] 表情覆盖在动作结束后恢复；
- [ ] 窗口置顶设置在重启后保持。

## 当前限制

- 主要针对 Windows 验证，尚未完成 macOS 和 Linux 适配；
- 命中蒙版来自默认 `wait` 姿势，不会逐帧跟随大幅度动作；
- 窗口固定为 `800 × 800`，缩放上限受窗口尺寸限制；
- PixiJS 4 构建时会出现 `path`、`url` 浏览器外部化警告；
- 动画状态机尚未在工作台显示当前阶段和等待动作；
- 尚未建立自动化 UI、截图对比和长时间性能测试；
- 尚未实现 AI、截屏、OCR、语音或联网环境感知功能。

## 环境感知路线

未来考虑让桌宠在用户明确授权下理解当前活动。该功能将采用本地优先、最小上传、可见可暂停的设计，不会直接做静默的高频全桌面上传。

```text
Phase 0：使用模拟活动数据验证回应策略
Phase 1：用户手动触发、预览确认、只分析活动窗口
Phase 2：本地敏感窗口拦截、OCR 脱敏与密钥安全存储
Phase 3：默认关闭的事件触发与冷却机制
Phase 4：本地视觉模型与可替换模型提供方
```

详细架构、风险模型和验收标准见 [1.7 桌面环境感知与隐私优先产品设计](<1.7（桌面环境感知与隐私优先产品设计）.md>)。

> 未经组织明确授权，不应在银行、企业办公或可能显示客户及内部数据的环境中启用云端截图分析。

## Git 与质量检查

建议以小步提交保留需求、实现、验证和复盘记录。常用提交类型：

```text
feat: 新功能
fix: 缺陷修复
refactor: 不改变行为的重构
docs: 文档调整
test: 测试相关
chore: 工具链与维护
```

```powershell
npm run build
```
